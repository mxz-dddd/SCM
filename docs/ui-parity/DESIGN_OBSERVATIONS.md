# 参考站布局与交互观察

## 已确认的宏观模式

- 1440×900 主视口下，左侧一级栏约 56 px，深色背景、图标在上文字在下，选中项使用高亮色块。
- 当前产品标识位于内容应用顶部左侧；产品内二级业务组横向排列。
- 顶部业务组只表达模块，不把创建、审批、打印、发运等动作塞入导航。
- 叶子页面在内容工作区或内部页签打开，产品切换不改变最外层 WorkStation URL，说明外壳通过独立应用/iframe 承载模块。
- 页面整体采用紧凑企业密度：小字号、低行高、窄工具栏、浅边框和大面积白色内容区。
- 仪表盘使用分区卡片和图表；列表页使用查询区、工具栏、表格、分页的稳定顺序。
- 入库订单和库存查询是高密度超宽表格，首行即列名/列过滤器；日期、状态和枚举使用列内筛选。参考站不是“把所有命令都铺满”的设计，导航、筛选和状态动作层级分离。
- 系统支持与数据大屏均为独立应用：帮助内容不提升为业务页面，大屏创建/导入/导出保留在页面动作层。

## 本地应采用的原创映射

- 保留澄链品牌、Ant Design 组件和现有 React/Router 实现，不复制参考站 iframe 架构、源码或品牌素材。
- 左侧栏改为 9～10 个本地业务大类；宽度和选中反馈参考观察值，但颜色、图标和文案原创。
- 二级导航放在一级栏右侧的固定业务导航区；每组展开显示三级叶子，避免横向菜单在窄屏溢出。
- 现有 Router、工作区 Tab、收藏、最近访问和命令面板继续共用一个类型化注册源。
- 现有大 Workbench 中的命令动作保留在页面工具栏/页签/抽屉，不制造假页面或空按钮。
- 共享 UI 提供列表、主从、任务、配置四种页面模板；列表模板先用于入库页，动作栏改为单行滚动，避免状态动作挤占多行内容。

## 已量化与待继续量化

- 固定取证视口为 1440×900；参考一级栏约 56 px，本地原创一级栏 72 px，以容纳可读的图形标记和两字短标签。
- 本地 10/10 一级模块均已实际点击，目标 URL、二级组、三级叶子与工作区 Tab 同步通过人工核验。
- 继续量化 Header/Tab 高度、查询区和表格行高；
- 列表、主从、任务工作台、配置页的代表页面结构；
- 抽屉、Modal、分页和详情页签的可见尺寸；
- 1366×768 与 1920×1080 的响应式行为。

这些指标将从只读 `getBoundingClientRect()` 与 computed style 提取，原始结果写入 `.artifacts/ui-reference/metrics/`，最终只提交抽象后的数值和差异结论。
