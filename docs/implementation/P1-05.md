# P1-05 ABAC 数据范围实现说明

## 规格映射

- PLT-006：数据策略按角色、资源和优先级保存显式表达式，支持组织、仓库、货主、伙伴、创建者、区域及 `custom.*` 受控属性；只允许 `EQ`/`IN` 和 `ALL`/`ANY`，非法字段、操作符或空集合直接拒绝。
- 账号角色与模板继承链共同决定可用策略；任一策略命中即 Allow，未配置或未命中时默认 Deny。决策记录命中策略、原因、权限版本、correlationId 和属性摘要，不保存原始敏感属性。
- 编译后的策略缓存键包含 tenant、account、resource 和 `permissionVersion`。策略变化递增直接或继承角色账号的权限版本，旧 JWT 失效且不会复用旧范围。
- `injectTenantAndDataScope` 始终通过 `AND` 注入可信 tenant 条件、调用方过滤和策略过滤，调用方即使传入其他 tenantId 也不能覆盖可信上下文。

## API 与事件

- `GET /api/v1/platform/data-policies`：按资源、优先级和代码稳定排序查询策略。
- `POST /api/v1/platform/data-policies`：创建并验证策略；需要 RBAC Guard 和 `Idempotency-Key`。
- `POST /api/v1/platform/data-policies/simulate`：对给定资源属性执行可解释的 Allow/Deny 模拟并写决策审计。
- 策略创建在同一事务写审计和 `platform.data-policy-created.v1` Outbox 事件。

## 验证记录

- 单元测试覆盖全部标准维度与自定义属性、正常命中、未命中、非法字段/操作符/空集合、权限版本缓存隔离，以及可信 tenant+scope 查询注入。
- PostgreSQL 冒烟覆盖策略列表、创建、语义一致幂等重放、非法表达式 400、匹配 Allow、默认 Deny，并确认审计只保存 64 位属性摘要。
- 独立空库依次应用四份迁移；种子连续执行两次后仍为十一项管理权限、六类资源，策略与决策审计表均存在。
