# P1-07 统一组件库与 Action Registry 实现说明

## 规格映射

- 按设计书 §4.2 提供 `QueryPanel`、`DataGrid`、`CommandBar`、`MasterDetail`、`StatusBadge`、`StatusStepper`、`BusinessTimeline`、`TaskWorkbench`、`BusinessDrawer`、`DecisionModal`、`ToastFeedback`、`NotificationCenter` 和 `FieldUpdater`。
- `DataGrid` 支持服务端页码回调、固定列标记、列显隐输入、受控批量选择、行右键动作、列配置和当前视图导出；`MasterDetail` 显示期望版本与当前版本冲突。
- `FieldUpdater` 只允许登记字段，禁止通过通用入口修改状态，并返回逐行成功与失败原因；查询条件可以稳定序列化为 URL 参数。
- 按设计书 §4.3 建立 Action Registry。页面顶栏、行菜单和详情底部可复用同一个动作决策，统一计算权限、数据范围、状态条件、确认文案和异步标识。
- Web 应用壳新增统一组件展示页，串联共享查询、动作、列表、状态、时间线、任务、批量更新和反馈组件。

## 不变量与边界

- Action Registry 对重复动作 ID 和未知动作 ID 立即拒绝；权限、数据范围和状态任一条件不满足时动作禁用，并返回稳定拒绝原因。
- 通用组件不持有业务域数据，也不直接访问任何域内部表；调用方负责服务端鉴权、状态机和持久化。
- 本卡是前端组件合同，不新增后端写 API、数据库状态转换或库存/时隙操作，因此写入幂等与并发测试不适用；后续业务卡接入动作时仍必须在服务端实现并验证。

## 验证记录

- Action Registry 单测覆盖多入口决策一致、权限拒绝、数据范围拒绝、状态拒绝和重复 ID。
- UI 渲染测试覆盖共享组件正常路径、版本冲突、异步动作标识、状态路径、时间线、消息中心和查询序列化。
- FieldUpdater 单测覆盖登记字段正常更新、状态条件导致的逐行失败以及禁止通用状态更新。
- Web 集成测试覆盖从应用壳打开组件页、查询面板、命令栏、状态禁用动作和版本冲突提示。
- `pnpm verify` 全绿；全仓 lint、TypeScript 和测试门禁通过。
