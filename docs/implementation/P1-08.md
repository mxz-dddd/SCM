# P1-08 配置、字典与单号实现说明

## 规格映射

- PLT-009：`ConfigVersion` 按租户、配置键、层级、范围与业务版本唯一保存不可变配置值，层级优先级为租户→组织→仓库→客户。草稿发布前返回新增/修改/删除差异并校验已发布依赖；支持 1–100% 稳定灰度、退役旧版和显式回滚，`ConfigPublishRecord` 留存每次发布动作。解析结果返回 `appliedVersionIds`，供业务对象记录实际使用版本。
- PLT-010：`BusinessDictionary` 与 `DictionaryItem` 支持分类、排序、扩展元数据和启停。关键原因码可要求备注和/或附件；停用只拒绝新业务使用，历史查询仍返回固定的代码/名称快照。
- PLT-011：`NumberRule` 支持租户、组织、业务类型、日期与流水模板，按 NEVER/年/月/日重置；号段预留使用单条 PostgreSQL 条件更新串行化同一规则的竞争，再写入不可变 `SequenceReservation`，不会逐号争抢数据库。
- 配置中心页面复用 QueryPanel、DataGrid、CommandBar、StatusBadge 与 Action Registry，覆盖服务端分页查询、差异预览、灰度发布、回滚、字典项启停、规则创建和号段预留。

## 权限、状态与一致性

- 所有端点先由 `PermissionGuard` 校验 `platform.configuration.read/write`，服务层再按账号种类和组织范围执行数据范围校验；普通用户不能读取或修改范围外组织/仓库和客户配置。
- 配置状态只允许 `DRAFT → PUBLISHED` 发布与 `RETIRED → PUBLISHED` 回滚；新版本发布原子退役同范围当前版本。字典项只允许 ACTIVE/INACTIVE 相互转换，同状态重复命令拒绝。
- 所有外部写 API 要求 `Idempotency-Key`；同键同内容返回原响应，同键异内容返回 409。配置、字典、规则与号段写入在同一事务中保存业务数据、审计和 Platform Outbox。
- API 返回对象 ID、乐观锁版本和 `accepted`；列表使用服务端页码、页长和稳定排序。BigInt 号段边界在响应中序列化为十进制字符串。

## API

- `GET/POST /api/v1/platform/configuration/config-versions`
- `GET /api/v1/platform/configuration/config-versions/{id}/preview`
- `POST /api/v1/platform/configuration/config-versions/{id}/publish|rollback`
- `GET /api/v1/platform/configuration/resolve`
- `GET/POST /api/v1/platform/configuration/dictionaries`
- `GET /api/v1/platform/configuration/dictionaries/{id}/items`
- `POST /api/v1/platform/configuration/dictionary-items/{id}/status|validate-use`
- `GET/POST /api/v1/platform/configuration/number-rules`
- `POST /api/v1/platform/configuration/number-rules/{id}/reservations`

## 验证记录

- 单元测试覆盖四层继承覆盖、差异计算、发布/回滚全部允许与拒绝转换、组织数据范围拒绝、原因码新用法/历史用法、周期键与单号格式。
- PostgreSQL 并发测试以 12 个事务竞争同一规则，生成 12 个互不重叠的 5 号号段；60 个号码唯一且连续。带数据库的 API 测试为 33/33 通过。
- 真实 API 冒烟完成依赖发布、v1/v2 发布与回滚、重复发布状态拒绝、403 权限拒绝、同键重放、异载荷 409、原因码停用与历史快照，以及相邻号段 `1–5`、`6–10`。
- 独立空库依次部署六份迁移，连续运行两次种子，六张配置相关表与约束均创建成功。
