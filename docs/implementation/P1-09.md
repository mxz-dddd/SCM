# P1-09 审计日志与变更历史实现说明

## 规格映射

- PLT-020：扩展 `PlatformAuditLog`，记录 LOGIN、SENSITIVE_QUERY、EXPORT、APPROVAL、API_CALL、BUSINESS_CHANGE、SECURITY 类别，以及结果、业务引用、请求方法/路径、查询条件、结果数、导出字段、before/after、correlationId、IP 和设备。
- 新增 `ChangeHistory` 保存资源、业务引用、动作、before/after、changedFields、操作者、trace/correlation、IP、设备与变更时点。迁移会回填已有带 before/after 的审计，之后由数据库触发器自动捕获，避免业务模块漏写。
- 登录成功/失败同步写入专用 LoginAudit 与统一 AuditLog；审计日志和 ChangeHistory 查询本身按 SENSITIVE_QUERY 留痕；导出记录保存筛选、字段和结果数量。
- 所有审计输入和响应递归脱敏 authorization、credential、password、secret、token、apiKey 等键。

## 不变量与安全

- AuditLog 与 ChangeHistory 只允许 INSERT。数据库 BEFORE UPDATE/DELETE 触发器统一抛出不可变错误；API 不提供修改或删除端点，业务用户无法绕过应用层删除审计。
- 所有查询按可信 JWT tenant 隔离，并使用服务端分页和 `createdAt/id` 或 `changedAt/id` 稳定排序。
- 查询需要 `platform.audit.read`，导出留痕需要 `platform.audit.export`；种子包含只授予 read/page/export 的 `SECURITY_AUDITOR` 只读角色，不含任何 write 权限。
- 导出是外部写命令，强制 `Idempotency-Key`；同键同载荷返回原 auditLogId，异载荷 409，并在同一事务写 AuditLog、IdempotencyRecord 和 Platform Outbox。
- 本卡对象没有可变业务状态机；数据库不可变拒绝即其状态不变量。不涉及库存或时隙，并发测试不适用。

## API

- `GET /api/v1/platform/audit/logs`：按类别、动作、业务引用、资源和时间范围分页查询，并记录敏感查询审计。
- `GET /api/v1/platform/audit/change-history`：按资源或业务引用分页查询不可变变更历史，并记录敏感查询审计。
- `POST /api/v1/platform/audit/exports`：记录当前审计视图的导出条件、字段与结果数；需要幂等键。

## 前端

- 应用壳新增只读审计中心，复用 QueryPanel、DataGrid、StatusBadge、BusinessTimeline、CommandBar 与 Action Registry。
- 页面支持服务端筛选/分页、选中记录脱敏详情、操作时间线和 ChangeHistory 列表；唯一命令是受权限和确认文案控制的导出留痕，没有编辑/删除动作。

## 验证记录

- 单元测试覆盖递归脱敏、稳定 changedFields、只读审计员权限集和迁移触发器存在性。
- PostgreSQL 测试覆盖带 before/after 审计自动生成 ChangeHistory，以及 AuditLog 更新/删除和 ChangeHistory 删除全部拒绝；带数据库 API 套件 37/37 通过。
- 真实 API 冒烟覆盖登录审计、敏感查询审计、嵌套凭证脱敏、导出正常路径、同键重放、异载荷 409、权限拒绝 403 和变更历史查询。
- 独立空库顺序部署七份迁移，连续运行两次种子；只读审计角色唯一，三组不可变/捕获触发器的五个触发事件齐全。
- `pnpm verify` 全绿；全仓 lint、TypeScript 和测试门禁通过。
