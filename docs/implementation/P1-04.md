# P1-04 组织与 RBAC 实现说明

## 规格映射

- PLT-002：组织类型覆盖集团、法人、事业部、仓库和运输组织；物化 `path` 支持继承与汇总。创建节点同步生成路径，移动节点先检查自身/后代循环和期望版本，再标记 `PENDING` 并由异步处理器重建整棵子树。
- PLT-005：权限资源覆盖菜单、页面、API、按钮、字段和导出；角色可继承模板，账号角色可配置租户级或组织子树范围，显式 `DENY` 优先于 `ALLOW`。
- NestJS `PermissionGuard` 对受保护命令和查询再次鉴权；前端按钮隐藏只用于体验，不是安全边界。每次决策都持久化 Allow/Deny、原因、权限代码、组织、资源和 correlationId。
- 角色权限变化会递增直接角色及继承角色账号的 `permissionVersion`，使旧 JWT 立即失效。

## API 与事件

- `GET/POST /api/v1/platform/organizations`：读取组织树或创建节点。
- `POST /api/v1/platform/organizations/:organizationId/moves`：提交移动，返回 202 和 `pathStatus=PENDING`。
- `GET/POST /api/v1/platform/roles`：读取权限目录/角色或创建角色及模板继承关系。
- `POST /api/v1/platform/roles/:roleId/grants`：替换指定权限的 Allow/Deny 授权。
- `POST /api/v1/platform/roles/:roleId/assignments`：按租户或组织范围向账号分配角色。
- 外部写命令使用 `Idempotency-Key`；组织移动产生 `platform.organization-path-rebuild-requested.v1`，角色授权产生 `platform.role-permissions-changed.v1`，并在同一事务写审计与 Outbox。

## 验证记录

- 单元测试覆盖组织路径、正常移动与循环拒绝、角色模板链（含错误循环保护）、组织范围继承、无范围越权拒绝、Deny 优先和六类资源完整性；通用幂等测试覆盖同载荷重放及异载荷冲突。
- PostgreSQL 冒烟覆盖组织读取/创建、创建与移动重放、循环 409、版本冲突 409、异步路径重建、无角色权限拒绝，以及模板权限继承 Allow→权限版本失效→显式 Deny。
- 独立空库依次应用三份迁移；种子连续执行两次后仍为一个组织、一个角色、九项权限、六类资源和一个账号角色分配。
