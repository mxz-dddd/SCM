# V2-03 OMS→WMS/TMS 履约过程管理器验收

## 结果

- OMS release 在同一事务创建 `OrderFulfillmentProcess`、命令步骤、自包含 v2 Outbox 事件，并保留 v1 事件作为只读兼容通知。
- `fulfillment.released.v2` 固化订单/履约版本、仓库/货主/客户/目的地、服务与路线快照，以及商品原单位和基础单位数量；`shipment.requested.v2` 固化地址、时间窗、重量/体积双单位、包装、车型、承运与费用责任快照。
- WMS/TMS 具名 consumer 通过 shared 运行时 validator 后分别调用 `OutboundService` 与 `TransportOrderService`，不读取 OMS 内部表；来源引用与版本唯一键保证重放不重复创建。
- OMS process consumer 只消费下游事实事件，创建事实完成后进入 `EXECUTING`，再由 `outbound.ready`、车辆分派、送达与 POD 确认依次推进等待步骤，所有生命周期步骤成功才进入 `COMPLETED`；同时更新跨域对象链接和履约投影。必需消费者永久死信时转 `MANUAL_INTERVENTION` 并由 Control 投影为去重 `AlertCase`。
- 显式 `retry-step` 重新发布原始 v2 命令事件，已成功分支保持不变；补偿命令只允许处理尚未创建目标对象的步骤，已有下游对象必须走目标域显式取消命令。
- Web 新增“履约过程中心”，统一使用 QueryPanel、DataGrid、Action Registry 展示过程、步骤、错误与对象链接，并提供受权限和状态控制的失败步骤重试。

## 数据库证据

- 新迁移：`20260716090000_v2_fulfillment_process`（expand）与 `20260716090100_v2_outbound_source_version_index`（经审查的 contract）。
- 全新空库 `scm_v2_wp03_final4` 从零部署 79/79 个迁移成功。
- 过程、步骤和跨域链接禁止物理删除；所有租户查询索引以 `tenant_id` 开头。

## 自动化证据

- 真实 PostgreSQL 测试验证 release 后一个 Outbound、一个 TransportOrder、一个 Process 和两条创建成功步骤；Process 保持 `EXECUTING`，不会过早完成。
- 同一 fulfillment v2 事件重放仍只有一个 Outbound。
- TMS handler 首次失败时 WMS 保持单实例，TMS 重试后成功且 Process 进入 `EXECUTING`。
- `outbound.ready`、车辆分派、送达、POD 确认事实按顺序推进其余四条步骤，最后 Process 才完成。
- 永久失败转人工介入，Control AlertCase 可见；显式 retry 只恢复 TMS 失败创建步骤，成功后回到 `EXECUTING`。
- Process 15 条、Step 17 条允许转换均由显式 transition-map 参数化测试守护，终态回退被拒绝。
- P2 Playwright 场景已改为启动真实 Worker 并轮询自动创建结果，release 后不再调用 WMS/TMS 创建接口。
- 独立空库真实 HTTP 验收 10/10 场景通过；全量 verify 通过 API 356、Web 31、Worker 15、Shared 30、UI 6 项测试。
