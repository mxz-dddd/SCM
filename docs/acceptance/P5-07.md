## 性能门槛

在开发模式真实 HTTP 服务完成预热后执行有界并发采样，使用最接近秩计算 P95；每个请求均校验成功状态和业务结果。

| 类型 | 样本/并发 | P95 | 最大值 | 门槛 | 结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| 运维工作台列表 | 100 / 10 | 34.21 ms | 38.66 ms | < 2,000 ms | 通过 |
| 运维信号写命令 | 100 / 10 | 22.22 ms | 23.48 ms | < 1,500 ms | 通过 |
| RF 拣选确认 | 50 / 单设备顺序提交 | 12.75 ms | 17.55 ms | < 800 ms | 通过 |

RF 场景校验每次扫描均生成唯一确认，累计 50 次后任务数量守恒并进入复核状态。该门禁用于回归发现明显退化，正式容量规划仍应按生产数据量、部署规格和网络条件持续压测。

## 跨租户自动化门禁

- 租户 A 的有效 JWT 携带租户 B 的 `X-Tenant-Id` 时返回 403 `TENANT_CONTEXT_MISMATCH`。
- 租户 A 使用本租户上下文引用租户 B 的备份资源时返回 404，租户 B 原记录保持 `PLANNED`、版本 1，未发生侧写或状态变化。
- 上述场景纳入 GitHub Actions `production-readiness` 作业，每次主分支推送和拉取请求均执行。

## 恢复与事件重放演练
