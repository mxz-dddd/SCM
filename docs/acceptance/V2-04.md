# V2-04 多租户 Worker Principal 验收

## 结果

- `TenantContext` 增加仅运行时可用的 `WORKER`；JWT 可签发的 AccountKind 仍只有平台管理员、租户管理员和普通用户。
- `SessionContextService` 对 `WORKER_CONTROL_TOKEN` 做 SHA-256 后恒时比较，要求 32+ 字符 token、专用 `WORKER_ACTOR_ID`、显式 `X-Tenant-Id` 和 ACTIVE 租户；不会查询或冒充租户管理员。
- 无租户头的内部发现端点提供最多 100 条的 cursor pagination，只返回 ACTIVE 租户的 id/code/name；普通 JWT 被拒绝。
- 全局 `WorkerAccessGuard` 对 WORKER 默认拒绝，31 个后台 operation 逐路由显式 allowlist；普通 JWT 继续执行原 RBAC。
- Worker 删除 `WORKER_TENANT_ID`，每 30 秒刷新租户，按可配置的有界并发轮询 Outbox、EventDelivery 和 Webhook；同进程按 operation+tenant 防重入，多进程继续依赖数据库 lease/`SKIP LOCKED`。
- graceful shutdown 停止新轮询并等待 in-flight；健康端点展示发现租户、刷新时间、五类 backlog、失败租户与 in-flight。

## 自动化证据

- 真实 PostgreSQL 验证一个 Worker token 发现并隔离处理租户 A/B，SUSPENDED 租户不出现。
- Guard 单元测试验证 WORKER 仅能访问显式 route，普通用户不会绕过 RBAC；Supervisor 测试验证游标翻页、有界处理和同租户防重入。
- 真实 HTTP E2E 验证普通 JWT 不能发现租户、Worker token 访问 `/api/v1/oms/orders` 返回 403、后台 backlog 可访问，真实 Worker 自动履约仍成功。
- EventDelivery、Webhook、Job 的数据库租约与并发测试继续守护多实例仅一次完成语义。
